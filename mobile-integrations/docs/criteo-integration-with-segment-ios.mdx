## Overview

Criteo serves personalized ads to mobile app users that have a high probability of clicking through and making a purchase. Criteo technology is based on real-time product recommendation optimization and prediction engines.

To enable its technology, Criteo needs:

- **App events** — App events and relevant data correctly captured on your mobile app.
- **Deep Link Capability** — Product level deep link capabilities in app to take users back to the products they clicked on.
- **Catalog Feed** — A CSV or XML file (called Catalog Feed) containing product information of a large portion of your mobile app's offers.

This document provides detailed information on the following:

- Integration
- Required events and parameters
- Implementation guidelines

## App Events & Data

### SDK Initialization

Set up and initialize the Segment SDK as recommended by the Segment documentation.

<Note>
  Find additional SDK & event tracking documentation here: [Segment iOS Source docs](https://segment.com/docs/sources/mobile/ios/) and [Segment Criteo Integration docs](https://segment.com/docs/integrations/criteo). The minimum supported SDK version for all Criteo related functionality is v3.15.0.
</Note>

#### Segment SDK Initialization

Ensure that the Segment SDK is initialized in `didFinishLaunchingWithOptions()`:

```objc
#import <Analytics/SEGAnalytics.h>
- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
{
    // Account Configuration info - must be set
    SEGAnalyticsConfiguration *configuration = [SEGAnalyticsConfiguration configurationWithWriteKey:@"Insert-Configuration-Key"];
    configuration.trackApplicationLifecycleEvents = YES;
    configuration.recordScreenViews = YES;
    [SEGAnalytics setupWithConfiguration:configuration];
    return YES;
}
```

### Events Implementation in the App

Criteo requires the implementation of the following events:

| Event Name | Retail Event Description |
| --- | --- |
| viewHome | App open / app brought to the foreground. |
| viewListing | View of a list of products. |
| viewProduct | View of a specific product. |
| viewBasket | View of shopping basket. |
| trackTransaction | Purchase of one or more products. |

#### View Home

The `viewHome` event is sent to Criteo on the `Application Opened` event.

```objc
[[SEGAnalytics sharedAnalytics] track:@"Application Opened" properties: @{
   @"url" : @"url://location" // deeplink that brought user into app (if deeplinked)
}];
```

#### View Listing

The `viewListing` event should be triggered on pages displaying product lists such as a category page or a search results page. It will automatically be sent to Criteo when the Segment "Product List Viewed" event fires. You must include the ID of the top three products displayed on the page/list. These IDs must match those used in the catalog feed. The format of the product information must be an array of product objects containing a `product_id` or `id` parameter. Example below.

Use the following code snippet to implement:

```objc
[[SEGAnalytics sharedAnalytics] track:@"Product List Viewed" properties: @{
        @"email": @"test@example.com", // Segment MD5 hashes email before sending to Criteo
        @"checkin_date" : @"10-20-2017", // checkin date  -- used for travel only
         @"checkout_date" : @"10-27-2017", // checkout date  -- used for travel only
        @"products": @[ @{@"product_id": @"abc123"},
                        @{@"product_id": @"def456"},
                        @{@"product_id": @"ghi789"}]
}];
```

#### View Product

The `viewProduct` event should be triggered on all product-detail pages. You must include the ID of the product detailed on the page via the `product_id` (or `id`) parameter in the `properties` dictionary. It must be the same ID as used in the catalog feed, and must be unique. Example below.

Use the following code snippet to implement:

```objc
[[SEGAnalytics sharedAnalytics] track:@"Product Viewed" properties: @{  
    @"email" : @"test@example.com", // Segment MD5 hashes email before sending to Criteo
    @"product_id" : @"507f1f77bcf86cd799439011",
    @"checkin_date" : @"10-20-2017", // checkin date -- used for travel only
    @"checkout_date": @"10-27-2017" // checkout date -- used for travel only
}];
```

#### View Basket

The `viewBasket` event will be triggered on the basket-details pages. You must include the ID, unit price, and quantity of the products in the basket/cart. Note: the product information for the `viewBasket` event & the `trackTransaction` event is expected to be an array of product objects (see below for example formatting).

Use the following code snippet to implement:

```objc
[[SEGAnalytics sharedAnalytics] track:@"Cart Viewed" properties: @{
    @"email" : @"test@example.com", // Segment MD5 hashes email before sending to Criteo
    @"currency" : @"USD",
    @"checkin_date" : @"10-20-2017", // checkin date -- used for travel only
    @"checkout_date": @"10-27-2017", // checkout date -- used for travel only
    @"products" : @[@{ @"id": @"abc123", @"price": @12.99, @"quantity": @2},
                    @{ @"id": @"aaa111", @"price": @2.99, @"quantity": @5}]
}];
```

#### Track Transaction

The `trackTransaction` event should be triggered on order confirmation pages. You must include the IDs, unit prices, and quantities of the products bought in the transaction via the `products` array. Again, the product information must be sent as an array of product objects like in the example below.

Use the following code snippet to implement:

```objc
[[SEGAnalytics sharedAnalytics] track:@"Completed Order" properties: @{
    @"orderId" : @"50314b8e9bcf000000000000",
    @"email" : @"test@example.com", // Segment MD5 hashes email before sending to Criteo
    @"checkin_date" : @"10-20-2017", // checkin date -- used for travel only
    @"checkout_date": @"10-27-2017", // checkout date -- used for travel only
    @"currency" : @"USD",
    @"products" : @[@{ @"id": @"abc123", @"price": @12.99, @"quantity": @2},
                    @{ @"id": @"def456", @"price": @2.99, @"quantity": @5},
                    @{ @"id": @"hij789", @"price": @9.99, @"quantity": @1}]
}];
```

## Dashboard Configuration

Once you begin sending Segment events from your application, activate the Criteo Integration in the Segment dashboard.

### Configuring Criteo in Segment Dashboard

To begin sending app events to Criteo:

1. In the Segment Dashboard, go to **Integrations** and then click the **Add Integration** button.
2. Search for and select the Criteo Integration. Then click **Configure Criteo**.

<Frame>
  ![Image](/images/mobile-integrations/segment/segment_configure_criteo_integration.png "Image")
</Frame>

3. Once you've added the Criteo Integration to your "source" (your app), you must activate the Integration.

<Frame>
  ![Image](/images/mobile-integrations/segment/segment_activate_integration.png "Image")
</Frame>

4. Once active, the Integration will automatically transform & forward your app events to Criteo.

<Frame>
  ![Image](/images/mobile-integrations/segment/segment_events_forwarded.png "Image")
</Frame>

## Catalog Feed

### Catalog Feed Overview

A catalog feed is an XML or a CSV file containing product information (name, price, deep link, image link…) that allows Criteo to dynamically generate the product recommendation banners. Therefore, it is important to keep this file up to date for Criteo to show the right data in your banners.

The following points need to be kept in mind:

- Each product must have a unique ID that must be identical to the one passed in the events.
- The catalog feed must contain all or at least most of your site's products.
- Recommended image resolution is 300x300 pixels to 400x400 pixels.

<Note>
  Criteo will already have the catalog feed in some instances (i.e. live campaigns on mobile, web, or desktop).
</Note>

For more information, please request the dedicated guide from your contact.

## Testing Process

You should contact Criteo to start the testing phase as soon as the events are implemented.

<Warning>
  Please allow sufficient time (at least a week before) for testing prior to the app submission in order to ensure that the data you are sending is complete.
</Warning>

Criteo will require the following elements:

- Pieces of implemented code for each event.
- App build to test the collection of events on Criteo's side.
- If remote testing, the IDFA of the device used to test the events.
