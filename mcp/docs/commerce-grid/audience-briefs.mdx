## Overview

The Commerce Grid Audience Briefs MCP lets your AI application or agent work with Commerce Grid audience planning briefs. Your agent can research AI-recommended audience segments, review audience insights, create briefs, find existing briefs, and share them through a link.

Typical uses include:

* **Researching audiences** for a campaign before committing to a brief
* **Creating audience planning briefs** from campaign details in natural language
* **Reviewing and sharing** existing briefs with stakeholders

***

## Add the endpoint

Add the Audience Briefs MCP as an MCP server in your MCP-compatible client or agent environment:

```
https://mcp.criteo.com/commerce-grid-supply-audience-briefs/mcp
```

Refer to [Access Flows](/mcp/docs/access-flows) for the step-by-step setup on Claude, ChatGPT, or other platforms.

Refer to [MCP Troubleshooting](/mcp/docs/mcp-troubleshooting) if you run into connection, authentication, or tool discovery issues.

<Info>
  Access to the Commerce Grid Audience Briefs MCP is set up by Criteo. Please reach out to your Criteo representative to get credentials for your use case before connecting.
</Info>

***

## Client selection

Most tools operate under a single Commerce Grid client (contract) and require a `clientId` parameter.

* Call `get_available_clients` first to list the clients available to the connected credentials.
* If more than one client is returned, the agent asks you which one to use.
* The selected client ID is then passed as `clientId` to every client-scoped tool.

<Note>
  Results are limited to the clients accessible to the credentials used by the MCP client. A brief can only be retrieved or shared under the client it belongs to.
</Note>

### Client discovery

<a id="get_available_clients" />

**`get_available_clients`**

Returns the clients (contracts) available to you. If more than one client is returned, choose the one to use; its ID must then be passed as `clientId` to client-scoped tools.

This tool takes no parameters.

<a id="segment-format" />

**Segment format**

Each segment in `segmentsJson` contains:

* **Required:** `skuKeywords`, `segmentSize`, `segmentType`, `description`, `relevanceScore`
* **Optional:** `dataProviderId`, `externalSegmentId`, `alreadyCreated`

Some segment types also require a targeting configuration:

| Segment type | Required configuration | Fields |
| :----------- | :--------------------- | :----- |
| InMarket | `inMarketConfiguration` | `country`, `buyingPower`, `gender`, `interestIds`, `brandIds`, `priceRange` |
| Affinity | `affinityConfiguration` | `country`, `targetingCategoryIds`, `customCategoryIds`, `lookbackDays`, `numberOfEvents` |

Other segment types do not require a configuration.

<Warning>
  Copy the complete configuration from the recommendation or segment details, even for segments that are already created. Preserve empty lists and a `null` gender, and never invent targeting values.
</Warning>

## Typical workflow

<Steps>
<Step title="Select the client">

Call `get_available_clients` to get the `clientId`. If several clients are available, pick the right one.
</Step>

<Step title="Research segments">

Call `get_recommended_segments`, then `get_segment_insights` to explore and compare segments. Nothing is saved at this stage.
</Step>

<Step title="Create the brief">

Call `create_brief_with_segments` with the segments you selected, or `create_brief` to let the MCP recommend segments for you.
</Step>

<Step title="Review the brief">

Call `query_briefs` or `get_brief_by_id` to find and review the brief.
</Step>

<Step title="Share the brief">

Call `share_brief` to get a shareable link.
</Step>
</Steps>
