## Context

Some regions require ads that contain AI content to be labelled to shoppers. Depending on the retailer's region, this means one of the following:

* **AI-generated or AI-modified content**: applies to the EU (27 member states), South Korea, India, Taiwan, Vietnam and Thailand.
* **Synthetic performers**: applies to the US states of New York and California.

Criteo records how each creative asset was produced (for example from C2PA content credentials embedded in the file) and returns that information in the delivery response, so that you can show the right label on the right ads.

Criteo tells you **what each asset contains** and **which disclosure rule applies to your retailer**. You decide **how to draw the label** on your site or app, following the rendering guidance below.

<Info>
  AI transparency is activated **retailer by retailer**. For a retailer where it is not activated, the delivery response does not change and no label is expected. To get it activated, reach out to your Criteo representative.
</Info>

<Note>
  This page covers Onsite Display formats. Sponsored Products placements do not carry these fields yet.
</Note>

***

## What changes in the ad delivery response

Once enabled for a retailer, two new fields are added to Onsite Display placements.

<Info>
  The two fields are sent to facilitate reading the AI label signals. They are not the only source of that information. The images and videos Criteo returns already carry their **C2PA manifest** in their metadata, whether or not the feature is enabled for your retailer, so you can read and parse the manifests yourself if you prefer. When the feature is enabled, Criteo reads them for you and returns the result in the delivery response.
</Info>

| Field | Where | Type | Description |
| --- | --- | --- | --- |
| `ai_disclosure_rules` | On the placement, next to `rendering` | array of strings | Which disclosure rule applies to this retailer. |
| `assets_generation_method` | Inside `rendering` | JSON-encoded object | For each asset in `rendering`, a number describing whether the asset contains AI content. |

For the values of `ai_disclosure_rules`, see [ai_disclosure_rules](#ai_disclosure_rules). For the values of `assets_generation_method` and what each number means, see [What each value means](#what-each-value-means) and the [Value reference](#value-reference). To know which label to show for a given combination, see [Which label to show](#which-label-to-show).

### Example

```json
{
  "placements": [
    {
      "viewHome_desktop-AboveGridFlagship": [
        {
          "format": "flagship",
          "rendering": {
            "desktop_background_image": "//retailmedia-static.criteo.com/creativeassets-live/desktop-bg.jpg",
            "desktop_background_image_alt_text": "Spring sale on snacks",
            "mobile_background_image": "//retailmedia-static.criteo.com/creativeassets-live/mobile-bg.jpg",
            "mobile_background_image_alt_text": "Spring sale on snacks",
            "mobile_logo_image": "//retailmedia-static.criteo.com/creativeassets-live/logo.png",
            "assets_generation_method": "{\"desktop_background_image\":33,\"mobile_background_image\":36,\"mobile_logo_image\":34}"
          },
          "ai_disclosure_rules": ["ai_content"],
          "OnLoadBeacon": "...",
          "OnViewBeacon": "...",
          "OnClickBeacon": "..."
        }
      ]
    }
  ]
}
```

In this example the desktop background has no AI content (`33`), the mobile background is AI-generated (`36`) and the logo is AI-modified (`34`).

### `assets_generation_method`

* The keys are the same asset names used elsewhere in `rendering` (`desktop_background_image`, `mobile_logo_image`, and so on).
* Like the other values in `rendering`, it is a **JSON-encoded string**. Parse it before use.
* In some formats, an asset key holds **several images** (an array of URLs in `rendering`). This is the case in the legacy **Butterfly** format, and it can also happen in custom formats. Its entry in `assets_generation_method` is then an **array of numbers in the same order** as the images:

```json
{
  "multiple_images": [
    "//retailmedia-static.criteo.com/creativeassets-live/AiGenerated.jpg",
    "//retailmedia-static.criteo.com/creativeassets-live/nonAi.jpg"
  ],
  "assets_generation_method": "{\"multiple_images\":[36,0]}"
}
```

* The property can be **absent** (for example on a creative with no information about its assets). Treat a missing property, a missing key or a value of `0` as "nothing to disclose".

### `ai_disclosure_rules`

| Value | Meaning | Typical regions |
| --- | --- | --- |
| `["ai_content"]` | The **AI Generated** / **AI Modified** rule applies. | EU (27 member states), South Korea, India, Taiwan, Vietnam and Thailand |
| `["synthetic_performer"]` | The **Ad Contains Synthetic Performer** rule applies. | US (New York and California only) |
| `[]` | No rule applies. Do not render any label. | Rest of the world |

<Warning>
  `ai_disclosure_rules` says which rule applies. It does **not** say that a label must be shown. Whether to show a label depends on the values in `assets_generation_method`.
</Warning>

A retailer receives only one rule: `ai_content` and `synthetic_performer` never apply together.

***

## What each value means

Each value in `assets_generation_method` is a **bitmask**: a sum of the flags below.

| Bit | Value | Meaning |
| --- | --- | --- |
| Non-AI | `1` | The asset was declared as not containing AI. |
| AI Modified | `2` | An existing asset was modified with AI. |
| AI Generated | `4` | The asset was generated by AI. |
| Synthetic Performer | `8` | The asset contains a synthetic performer. |
| Source: self declaration | `16` | The information was declared by the advertiser. |
| Source: C2PA | `32` | The information was read from C2PA content credentials in the file. |

The flags can be combined. For example, `38` = `32 + 4 + 2`: from C2PA, **AI Generated** and **AI Modified**.

<Note>
  The source flags (`16` and `32`) only tell you where the information comes from. They never change which label is shown.
</Note>

<Info>
  For the initial rollout, no self declaration is available yet. The values you can receive are `0`, `33`, `34`, `36`, `38`, `40`, `42`, `44` and `46`.
</Info>

## Which label to show

Combine the rule from `ai_disclosure_rules` with the flags of each asset:

| Asset contains | Rule `ai_content` | Rule `synthetic_performer` |
| --- | --- | --- |
| Nothing flagged (`0`, `1`, `33`) | No label | No label |
| AI Modified only | **AI Modified** | No label |
| AI Generated (with or without AI Modified) | **AI Generated** | No label |
| Synthetic Performer (with or without AI flags) | AI Generated / AI Modified, if the asset also carries those flags; otherwise no label | **Ad Contains Synthetic Performer** |

A few rules to keep in mind:

* **One label per ad.** If different assets of the same ad return different values, show a single label: the most restrictive one **for your rule**. Under `ai_content`, **AI Generated** wins over **AI Modified**. Under `synthetic_performer`, the label applies as soon as one asset contains a synthetic performer, even if the other assets do not. The two rules are never combined, so there is no ranking between synthetic performer and AI Generated.
* **Only the label for your rule.** Under `ai_content`, ignore the synthetic performer flag. Under `synthetic_performer`, ignore the AI Generated and AI Modified flags.
* **Empty `ai_disclosure_rules`: no label**, whatever the values are.
* **Evaluate the assets you actually display.** Use the entries for the images shown in the current rendering (for example the `mobile_*` assets on a mobile layout), and every item of an array.

### Recommended display

For **AI Generated** and **AI Modified**, we recommend showing a compact **"AI"** label that expands to its full wording, **"AI Modified"** or **"AI Generated"**, when the shopper hovers over it (or taps it on touch devices). The **Ad Contains Synthetic Performer** label is different: always show its full text, without any interaction.

For where to place the label and how to style it on each format, see [How to render the label](#how-to-render-the-label).

## How to render the label

### Recommended label

* **AI Generated / AI Modified**: a **round AI badge**, always visible. Its full wording appears on hover (desktop) or on click or tap (mobile and app).
* **Alternative**: a sparkle icon with the text "AI info" is also accepted for AI Generated and AI Modified, in line with the IAB recommendation.
* **Ad Contains Synthetic Performer**: always show the full text next to a monochrome sparkle. **Never hide it.** For tight spaces such as the 160×600, use the compact version: one line, 10px.

### Placement

* Place the label in the **top-right corner of the branding zone** for most standard Onsite Display formats, for consistency across formats.
* Inside grids, keep the label **within the boundaries of the format**.
* When there is free space around a format, the label can sit **outside the format**, close to the content it refers to.

### Color

Legacy Onsite Display and IAB formats do not pass a color mode in the ad response, so the label defaults to the **Dark** mode. You can override it.

### Playground

To preview the label on each Onsite Display format, on desktop and mobile, with your own creative if you want, use the <a href="/retailer-integration/docs/ai-label-playground" target="_blank" rel="noopener noreferrer">AI label playground</a> (opens in a new tab). Your creative stays in your browser and is not sent anywhere.

<Note>
  Format-specific implementation details will be added to each format page when the feature is available on all formats.
</Note>

## Reading the response

This function turns a placement into the single label to show. It reads the asset values, applies the rule and returns the most restrictive label, or `null`.

```javascript
// Bit flags of a generation method value
const AI_MODIFIED = 2;
const AI_GENERATED = 4;
const SYNTHETIC_PERFORMER = 8;

function resolveAiLabel(item, displayedAssets) {
  const rules = item.ai_disclosure_rules || [];
  if (rules.length === 0) return null;                  // no rule: no label

  let methods = item.rendering && item.rendering.assets_generation_method;
  if (!methods) return null;                            // nothing declared
  if (typeof methods === "string") methods = JSON.parse(methods);

  // Flatten single values and arrays, for the assets you display only
  const values = displayedAssets
    .flatMap((key) => [].concat(methods[key] ?? 0));

  const has = (flag) => values.some((v) => (v & flag) !== 0);

  if (rules.includes("synthetic_performer") && has(SYNTHETIC_PERFORMER)) {
    return "Ad Contains Synthetic Performer";           // always visible
  }
  if (rules.includes("ai_content")) {
    if (has(AI_GENERATED)) return "AI Generated";
    if (has(AI_MODIFIED)) return "AI Modified";
  }
  return null;
}

// Example: mobile layout of the response above
// resolveAiLabel(item, ["mobile_background_image", "mobile_logo_image"]) -> "AI Generated"
```
