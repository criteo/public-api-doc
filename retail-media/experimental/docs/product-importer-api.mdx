---
title: Import Products to Catalog
description: How to submit product insertions, updates, and deletions to Criteo's catalog using the Product Importer batch API.
---

This guide covers submitting a batch of product changes and checking their import status. By the end, your products will be updated in Criteo's catalog and eligible to serve in campaigns.

---

## Prerequisites

- **Auth scope**: `retail-media:manage` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Merchant ID**: the `merchantId` that owns the catalog
- **Regional URL**: use the endpoint matching your region — `api.us.criteo.com` (Americas), `api.as.criteo.com` (APAC), `api.eu.criteo.com` (EMEA)

---

## Steps

### 1. Submit the product batch

[→ `POST /retail-media/catalog/products/batch`](/retail-media/experimental/reference/catalog/submit-product-batch)

Send up to 1,000 product operations in a single request. Each entry needs a `merchantId`, a `method` (`insert`, `update`, or `delete`), and a `product` object.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/catalog/products/batch" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "entries": [
      {
        "merchantId": "123456",
        "method": "insert",
        "product": {
          "id": "sku-12345",
          "title": "Trail Running Shoes - Blue",
          "description": "Lightweight trail shoe for all terrains",
          "link": "https://www.example.com/trail-shoes-blue",
          "imageLink": "https://www.example.com/images/trail-shoes-blue.jpg",
          "brand": "ExampleBrand",
          "gtin": "0123456789012",
          "price": "89.99 USD",
          "availability": "in stock",
          "itemGroupId": "trail-shoes-group"
        }
      }
    ]
  }'
```

Save the `operationToken` from the response — it's used to poll for import status.

<Warning>
  One `merchantId` per batch request. Including the same product ID more than once in a single batch is not allowed and will cause the entire batch to fail.
</Warning>

### 2. Poll for import status

[→ `GET /retail-media/catalog/products/batch/report/{operationToken}`](/retail-media/experimental/reference/catalog/get-product-batch-report)

Poll until the response indicates the batch has completed. Status values: `accepted` (queued), `validated` (processed successfully), `failed` (errors in the batch — check the report for details).

---

## Verify

A successful batch submission returns HTTP `200` with an `operationToken`. After polling to `validated`, the products are in Criteo's catalog. If the status is `failed`, the report contains per-product error details.

---

## Best Practices

- **Only send changed products.** This API is not a feed ingestion mechanism — submit only new, updated, or deleted products.
- **Don't batch unchanged products.** Unnecessary updates create noise and slow processing.
- **Products expire after 30 days** unless you set `expirationDate` (max 1 year from today).
- **Submit deletions immediately** when a product is removed from your store — don't rely on expiration.
- **Include `itemGroupId` when deleting a variant** to avoid catalog inconsistencies.

---

## Constraints

| Limit | Value |
|---|---|
| Max products per batch | 1,000 |
| `merchantId` per request | One only |
| Duplicate product ID in one batch | Rejected — the entire batch fails |
| `method` values | `insert`, `update`, `delete` |
| Product expiry | 30 days after last update (extend with `expirationDate`, max 1 year) |
| `id` vs `itemGroupId` | Must be different and in different value ranges — do not mix them up |
| Regional URLs | Americas: `api.us.criteo.com` · APAC: `api.as.criteo.com` · EMEA: `api.eu.criteo.com` |
