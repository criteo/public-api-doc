---
title: Monitor Catalog Ingestion
description: How to check catalog import status and diagnose data quality issues for a merchant.
---

Use these endpoints to verify that catalog imports are running and to identify what's blocking or failing them.

---

## Prerequisites

- **Auth scope**: `retail-media:read` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Merchant ID**: the `merchant-id` whose ingestion history to retrieve

---

## Steps

### 1. List recent ingestions

[→ `GET /retail-media/catalog/merchants/{merchant-id}/ingestion/reports`](/retail-media/experimental/reference/catalog/list-ingestion-reports)

Returns recent ingestion runs ordered most-recent-first. Check `ingestionStatus` for each run:

| Status | Meaning |
|---|---|
| `inProgress` | Still running — poll again |
| `finished` | Completed successfully |
| `failed` | System error — fetch the summary report for the error message |
| `blocked` | Catalog rejected by data quality rules — fetch the summary report to identify the failing fields |

```bash
curl -X GET "https://api.criteo.com/experimental/retail-media/catalog/merchants/987654321/ingestion/reports?limit=25&offset=0" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Accept: application/json"
```

Save `data[].id` from any `blocked` or `failed` entry — this is the `ingestionId` for the summary report.

<Note>
  `blocked` is not a system failure. It means the catalog data did not pass quality validation (e.g., missing price, GTIN, or title on too many products). The catalog was not published.
</Note>

### 2. Fetch the ingestion summary

[→ `GET /retail-media/catalog/ingestion/{ingestion-id}/reports/summary`](/retail-media/experimental/reference/catalog/get-ingestion-summary)

Returns full diagnostic detail: trigger, volume counts, delta (added/updated/deleted/unchanged offers), and data quality breakdowns. If `ingestionStatus` is `blocked`, inspect `dataQuality.errors` to see which fields are causing the most rejections.

---

## Verify

A successful list returns HTTP `200` with a `data` array. For a healthy catalog, the most recent entry has `ingestionStatus: finished` and `delta.addedOffers` or `delta.updatedOffers` matching your expected changes. A `blocked` ingestion with `dataQuality.quality` failing indicates catalog content issues to fix upstream.

---

## Constraints

| Limit | Value |
|---|---|
| List page size | 1–100 (default 25) |
| `ingestionType` | `catalogImport` or `productImporter` |
| `multiSourceReportingStatus` | `notEnabled`, `inProgress`, `success`, `failed` |
