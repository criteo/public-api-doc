---
title: Check Audience and Segment Size
description: How to estimate or compute the reach of an audience or audience segment before assigning it to a campaign.
---

Use these endpoints to preview reach before creating an audience, or to verify the size of an existing audience or segment after creation.

<Warning>
  Your app must have the **Audiences Read** permission enabled to use these endpoints.
</Warning>

---

## Prerequisites

- **Auth scope**: `retail-media:read` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Account ID**: the `accountId` that owns the audiences or segments
- For compute endpoints: one or more saved audience or segment IDs
- For estimate endpoints: an inline `algebra` or `events` definition

---

## Steps

### 1. Estimate audience size from an algebra definition

[→ `POST /retail-media/accounts/{account-id}/audiences/estimate-size`](/retail-media/experimental/reference/audience/estimate-audience-size)

Provide `retailerId`, `channel`, and an `algebra` object combining segment IDs with `and`, `or`, `not`. Use this to preview reach before saving the audience.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/accounts/4567891234567891/audiences/estimate-size" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "attributes": {
        "retailerId": "1141",
        "channel": "Onsite",
        "algebra": {
          "and": [
            { "audienceSegmentId": "738406687217913856" },
            { "not": { "audienceSegmentId": "735693505849913344" } }
          ]
        }
      }
    }
  }'
```

<Warning>
  The estimate endpoints are resource-intensive — bulk processing is not supported. Send one definition per request.
</Warning>

### 2. Compute size for saved audiences

[→ `POST /retail-media/accounts/{account-id}/audiences/compute-sizes`](/retail-media/experimental/reference/audience/compute-audience-sizes)

Pass an array of saved audience IDs and a `channel`. Returns `size` and `relativeSize` for each.

### 3. Estimate segment size from an events definition

[→ `POST /retail-media/accounts/{account-id}/audience-segments/estimate-size`](/retail-media/experimental/reference/audience/estimate-audience-segment-size)

Provide `retailerId`, `channel`, and an `events` object with `shopperActivity`, `lookbackDays`, and at least one of `categoryIds` or `brandIds`.

### 4. Compute size for saved segments

[→ `POST /retail-media/accounts/{account-id}/audience-segments/compute-sizes`](/retail-media/experimental/reference/audience/compute-audience-segment-sizes)

Pass an array of saved segment IDs and a `channel`. Returns `size` and `relativeSize` for each.

---

## Verify

A successful response returns HTTP `200` with `data.attributes.size` (absolute user count) and `data.attributes.relativeSize` (share of the retailer's total audience). If `size` is absent, your app lacks permission to view it. A `200` with `audience-size-too-small` in `errors` means the audience is below the minimum threshold of 20 users.

---

## Constraints

| Limit | Value |
|---|---|
| `channel` | `Onsite`, `Offsite` (case-insensitive) |
| Estimate endpoints | Single definition only — no bulk |
| `events.shopperActivity` | `View`, `Buy`, `AddToCart`, `Unknown` |
| `events.lookbackDays` | `Last7Days` through `Last180Days` (7, 14, 30, 45, 60, 90, 120, 150, 180) |
| Minimum audience size | 20 users — below this, `audience-size-too-small` is returned |
