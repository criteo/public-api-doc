---
title: Grant Third-Party Consent
description: How to programmatically grant API consent for private market demand accounts using the Admin and Business app model.
---

This guide covers the two-app consent flow for third-party private market integrations: set up an Admin app to grant consent, and a Business app to operate on behalf of demand accounts. By the end, you will have a Business app token linked to a demand account and ready for API calls.

<Note>
  Third-party consent granting only works for private market accounts created via your Admin app. For legacy accounts set up outside this flow, use the standard [Consent URL Generation](/criteo-apis/docs/consent-url-generation) process.
</Note>

---

## Prerequisites

- **Admin app** (Client Credentials) with the `Third-Party Accounts` domain on `Manage` access — created at [partners.criteo.com](https://partners.criteo.com)
- **Business app** (Authorization Code) with all relevant domains selected — created at [partners.criteo.com](https://partners.criteo.com)
- **Demand account ID**: the account to which consent will be granted — from [Create and Manage Third-Party Accounts](/retail-media/experimental/docs/account-creation-management-third-party)
- **Business app callback URL**: a registered redirect URI in your Business app settings

---

## Steps

### 1. Authenticate with the Admin app

[→ `POST /oauth2/token`](/retail-media/experimental/docs/authentication)

```bash
curl -X POST "https://api.criteo.com/oauth2/token" \
  -d "grant_type=client_credentials" \
  -d "client_id={ADMIN_CLIENT_ID}" \
  -d "client_secret={ADMIN_CLIENT_SECRET}"
```

Save the `access_token` from the response — it expires in 900 seconds.

### 2. Grant consent for the demand account

[→ `POST /retail-media/accounts/{accountId}/grant-third-party-consent`](/retail-media/experimental/reference/thirdpartyaccounts/grant-third-party-consent)

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/accounts/{DEMAND_ACCOUNT_ID}/grant-third-party-consent" \
  -H "Authorization: Bearer <ADMIN_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "GrantConsentModel",
      "attributes": {
        "clientId": "{BUSINESS_APP_CLIENT_ID}",
        "callbackUrl": "{BUSINESS_APP_CALLBACK_URL}",
        "callbackState": "{DEMAND_ACCOUNT_ID}"
      }
    }
  }'
```

A successful call returns HTTP `204`. Your callback URL will immediately receive a `code` parameter.

<Note>
  `callbackState` is optional but recommended — pass the demand account ID so you can associate the returned token with the correct account.
</Note>

### 3. Exchange the authorization code for a Business app token

[→ `POST /oauth2/token`](/retail-media/experimental/docs/authentication)

```bash
curl -X POST "https://api.criteo.com/oauth2/token" \
  -d "grant_type=authorization_code" \
  -d "client_id={BUSINESS_APP_CLIENT_ID}" \
  -d "client_secret={BUSINESS_APP_CLIENT_SECRET}" \
  -d "code={CODE_FROM_CALLBACK}" \
  -d "redirect_uri={BUSINESS_APP_CALLBACK_URL}"
```

The response includes an `access_token` and a `refresh_token`. Use the Business app token for all subsequent API calls on behalf of this demand account.

### 4. Refresh the Business app token

```bash
curl -X POST "https://api.criteo.com/oauth2/token" \
  -d "grant_type=refresh_token" \
  -d "refresh_token={REFRESH_TOKEN}" \
  -d "client_id={BUSINESS_APP_CLIENT_ID}" \
  -d "client_secret={BUSINESS_APP_CLIENT_SECRET}"
```

---

## Verify

A successful consent grant returns HTTP `204` with no body. The callback URL receives a `code` within seconds. If no callback arrives, confirm the `callbackUrl` matches the redirect URI registered in your Business app settings.

---

## Constraints

| Limit | Value |
|---|---|
| Admin app token expiry | 900 seconds — re-authenticate before granting multiple consents |
| Scope | Admin app must have `Third-Party Accounts` domain on `Manage` access only |
| Legacy accounts | Not supported — use standard consent flow for pre-existing accounts |
