This guide covers creating and updating a Sponsored Products auction line item using the campaign-scoped endpoints. By the end, you will have a Sponsored Products line item ready to serve.

---

## Prerequisites

- **Auth scope**: `retail-media:manage` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Campaign ID**: an existing Sponsored Products campaign ID from [Manage Campaigns](/retail-media/experimental/docs/campaigns-endpoints)
- **Retailer ID**: the retailer where ads will serve

---

## Steps

### 1. Create a Sponsored Products line item

[→ `POST /retail-media/campaigns/{campaign-id}/auction-line-items`](/retail-media/experimental/reference/line-item/create-auction-line-item)

Provide `name`, `campaignId`, `targetRetailerId`, `startDate`, `bidStrategy`, `optimizationStrategy`, and `targetBid`. `campaignId` and `targetRetailerId` are immutable after creation.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/campaigns/987654321/auction-line-items" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "SponsoredProductsLineItem",
      "attributes": {
        "name": "Back-to-school SP — Search",
        "campaignId": "987654321",
        "targetRetailerId": "1141",
        "startDate": "2026-11-02T00:00:00Z",
        "bidStrategy": "manual",
        "optimizationStrategy": "conversion",
        "targetBid": 0.80
      }
    }
  }'
```

Save `data.id` from the response — this is the `lineItemId` for subsequent calls.

<Warning>
  `targetBid` must be at or above the highest `minBid` across all products in the line item. The `minBid` per product is available from the catalog. The line item will not deliver until this condition is met.
</Warning>

### 2. Update a line item

[→ `PUT /retail-media/auction-line-items/{lineItemId}`](/retail-media/experimental/reference/line-item/update-auction-line-item)

PUT is a full replace — include every writable field or it will be set to `null`. Omitting `endDate` or setting it to `null` causes the line item to serve indefinitely.

### 3. Set status

A line item's `status` can only be set to `active` or `paused` by API. Other status values (`draft`, `scheduled`, `ended`, `archived`) are applied automatically based on dates and budget conditions.

---

## Verify

A successful create returns HTTP `200` with the new `lineItemId` in `data.id`. Confirm `data.attributes.status` is either `draft` (future start date) or `active` (start date in the past). If the line item shows `draft` unexpectedly, check that `targetBid` meets the catalog `minBid` for all products.

---

## Constraints

| Limit | Value |
|---|---|
| `campaignId`, `targetRetailerId` | Immutable after creation |
| `optimizationStrategy` | `conversion` (default), `revenue`, `clicks` |
| `maxBid` | Always enforced — overrides keyword-level bids; not applicable for `clicks` strategy |
| `targetBid` | Must meet `minBid` for all products in the line item |
| `endDate` | Nullable — omit or set to `null` for indefinite serving |
| Date format | `yyyy-MM-ddTHH:mm:ss±hh:mm` (timezone offset supported); defaults to UTC if omitted |
| `status` user-settable | `active` or `paused` only; other values are auto-managed |
| Keyword auto-approval | Already in keyword model → auto-approved; competitor brand name → auto-rejected; unknown → manual review |
