## Overview

Use the Line Item Diagnostics endpoint to check whether a line item is configured correctly. The response reports a status for each evaluated line item and, when requested, the configuration context, evaluated parameters, and issues that require attention.

Your access token must be authorized to view the selected resource. See [Authentication](/retail-media/experimental/docs/authentication).

## Endpoint

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/diagnostics/line-item-checks` | Diagnose line item configuration for a single line item or all line items in a campaign. |

## Get Line Item Diagnostics

<EndpointBadge method="get">
```http
https://api.criteo.com/experimental/retail-media/diagnostics/line-item-checks
```
</EndpointBadge>

Send exactly one resource selector: `line-item-id` or `campaign-id`. A line-item request returns one result. A campaign request returns results for all line items, paginated.

### Query Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `line-item-id` | string | One selector is required | ID of the line item to evaluate. Do not send it with `campaign-id`. |
| `campaign-id` | string | One selector is required | ID of the campaign whose line items to evaluate. Do not send it with `line-item-id`. |
| `use-approved-targeting` | boolean | No | When `true` (default), this checks the line item's approved targeting. When `false`, it checks the targeting changes awaiting approval. |
| `fields` | string | No | Comma-separated optional attributes to return: `context`, `issues`, and `parameters`. When omitted, all three are returned. `status` and `systemData` are always returned; requesting them produces an `invalid-fields` warning. |
| `cursor` | string | No | Continuation token from the previous campaign response's `meta.cursor`. Only valid with `campaign-id`. Omit it for the first page; for subsequent pages, pass the returned value unchanged without interpreting its format. |
| `limit` | integer | No | Maximum results in a campaign page. Applies only to `campaign-id` requests. Accepts values from `1` to `25` and defaults to `25`. |

### Response Attributes

Each result is in `data[].attributes`.

| Attribute | Type | Description |
| --- | --- | --- |
| `status` | string | `CanFullyServe`, `CanPartiallyServe`, `CannotServe`, or `Unknown`. Always included. |
| `systemData` | object | Check and source timestamps: `checkTime`, `lineItemCreatedTime`, and `lineItemUpdatedTime`. Always included. |
| `context` | object | IDs and types associated with the check: `accountId`, `campaignId`, `retailerId`, `lineItemId`, `campaignType`, and `buyType`. |
| `parameters` | object | Name/value pairs used while evaluating rules. |
| `issues` | array | Issues found in the line item's configuration. Each issue includes `ruleId`, `ruleName`, `code`, `severity`, `tags`, `format`, `outputParameters`, `message`, `id`, and optional `parentId`. |

### Status Values

| Status | Description |
| --- | --- |
| `CanFullyServe` | The line item is correctly configured, with no identified issues that limit serving. |
| `CanPartiallyServe` | The line item can serve in some contexts, but one or more issues limit serving. |
| `CannotServe` | Configuration issues prevent the line item from serving. |
| `Unknown` | The check could not complete. Inspect `warnings` and retry later. |

### Campaign Pagination

For campaign requests, the top-level `meta` object contains:

| Field | Description |
| --- | --- |
| `cursor` | Continuation token for the next page, or `null` when no next page is available. |
| `limit` | Maximum number of results per page. |
| `count` | Total number of line items in the campaign result set. |

The top-level `links` object provides URLs for navigating campaign results:

| Link | Description |
| --- | --- |
| `first` | URL for the first page, without a cursor. |
| `prev` | URL for the previous page, or `null` when unavailable. |
| `next` | URL for the next page, or `null` when traversal is complete. |
| `last` | URL for the last page, or `null` when unavailable without traversing the collection. |

### Campaign Pagination Example

Use `campaign-id` to check a campaign's line items. This example requests up to 25 results per page and includes only `context` among the optional attributes.

<Accordion title="Example request">

```bash
curl -L -X GET \
  'https://api.criteo.com/experimental/retail-media/diagnostics/line-item-checks?campaign-id=99887766&limit=25&fields=context' \
  -H 'Accept: application/json' \
  -H 'Authorization: Bearer <MY_ACCESS_TOKEN>'
```

</Accordion>

Here, `meta.count` is the total number of line items in the campaign result set, while `meta.limit` is the page size. Alternatively, pass `meta.cursor` unchanged in the next request's `cursor` query parameter, retaining the other query parameters.

### Result Availability

A recoverable dependency failure during a line item check returns `200 OK` with `status` set to `Unknown` and a `result-unavailable` warning. Treat this as an incomplete result and retry later; do not interpret it as confirmation that the line item can serve.

<Accordion title="Example response with Unknown status (200 OK)">

The following example shows a check that could not complete because a dependent service was unavailable. Optional attributes are omitted for brevity; source timestamps use their default values because the line item data could not be retrieved.

```json
{
  "data": [
    {
      "type": "LineItemCheck",
      "attributes": {
        "status": "Unknown",
        "systemData": {
          "checkTime": "2026-10-21T14:30:00Z",
          "lineItemCreatedTime": "0001-01-01T00:00:00",
          "lineItemUpdatedTime": "0001-01-01T00:00:00"
        }
      }
    }
  ],
  "warnings": [
    {
      "code": "result-unavailable",
      "type": "availability",
      "title": "The result could not be determined",
      "detail": "The result for line item 112233445566778899 could not be determined because a dependent service was unavailable."
    }
  ],
  "errors": []
}
```

</Accordion>

<Accordion title="Example error response (400)">

A campaign request with an invalid or malformed `cursor` returns `400 Bad Request`:

```json
{
  "warnings": [],
  "errors": [
    {
      "code": "invalid-cursor",
      "type": "validation",
      "title": "The request couldn't be validated.",
      "detail": "The cursor is invalid or malformed. Request the first page again to obtain a new cursor."
    }
  ]
}
```

Retry the campaign request without `cursor` to retrieve the first page and obtain a new continuation token.

</Accordion>

### Errors

| HTTP status | Code | Description |
| --- | --- | --- |
| `400` | `request-invalid` | Both or neither selector was supplied. |
| `400` | `invalid-limit` | The requested campaign page size is outside the supported range of `1` to `25`. |
| `400` | `invalid-cursor` | The cursor is malformed or does not represent a valid continuation position. Request the first page again to obtain a new cursor. |
| `400` | `invalid-fields` | `fields` contains an unsupported or duplicate optional field. |
| `401` | — | The caller is not authenticated. |
| `403` | `not-authorized` | The resource does not exist, has an invalid ID, or the caller cannot access it. |
