---
title: Request an Offsite Report
description: How to submit an offsite report request and retrieve the results using the async reporting flow.
---

This guide covers submitting an offsite performance report request and downloading the output. By the end, you will have a report with offsite campaign metrics broken down by the dimensions of your choice.

---

## Prerequisites

- **Auth scope**: `retail-media:read` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Account ID**: an `accountId` with active offsite campaigns — obtained from [your account list](/retail-media/experimental/reference/gateway/get-me)
- **Status and output endpoints**: use the stable equivalents at `GET /2026-07/retail-media/reports/{reportId}/status` and `GET /2026-07/retail-media/reports/{reportId}/output` to poll and download

---

## Steps

### 1. Submit the offsite report request

[→ `POST /retail-media/reports/offsite`](/retail-media/experimental/reference/analytics/create-offsite-report)

Provide `accountIds`, `startDate`, `endDate`, and your desired `metrics` and `dimensions`. All four are required when using custom metrics/dimensions.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/reports/offsite" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "RetailMediaReportRequest",
      "attributes": {
        "accountIds": ["563116287072485376"],
        "startDate": "2026-10-01",
        "endDate": "2026-10-31",
        "dimensions": ["date", "campaignId", "campaignName", "lineItemId", "mediaType", "publisher"],
        "metrics": ["impressions", "clicks", "spend", "attributedSales", "roas"],
        "format": "csv",
        "clickAttributionWindow": "7D",
        "viewAttributionWindow": "1D",
        "timezone": "UTC"
      }
    }
  }'
```

Save `data.id` from the response — this is the `reportId` used to poll for status.

<Warning>
  If you provide both `metrics`/`dimensions` and `reportType`, the `reportType` is silently ignored. Use one or the other.
</Warning>

<Note>
  `winRate` is only available for Sponsored Products campaigns. When requesting it, either set `campaignType: sponsoredProducts` or include `campaignTypeName` in your `dimensions`.
</Note>

### 2. Poll for status

[→ `GET /2026-07/retail-media/reports/{reportId}/status`](/retail-media/reference/analytics/get-report-status)

Poll until `data.attributes.status` is `success`. Retry on `pending` or `running`. On `failure`, the request was invalid — do not retry without changing the parameters.

The `expiresAt` field in the response indicates when the report output will expire (cached for at least 1 hour).

### 3. Download the output

[→ `GET /2026-07/retail-media/reports/{reportId}/output`](/retail-media/reference/analytics/get-report-output)

Returns the report data in the format specified at submission (`json`, `json-compact`, `json-newline`, or `csv`).

---

## Verify

A successful submission returns HTTP `200` with a `data.id` (the `reportId`). After polling, confirm `data.attributes.status` is `success` before downloading. A `410` response on the output endpoint means the report expired — resubmit the request.

---

## Constraints

| Limit | Value |
|---|---|
| Max date range | 100 days |
| Max account IDs per request | 50 |
| Report cache | At least 1 hour — check `expiresAt` in the status response |
| Offsite-specific dimensions | `adFormatSize`, `billingType`, `inventoryType`, `mediaType`, `publisher`, `ssp` |
| `reportType` | Ignored when `metrics` and `dimensions` are provided |
