---
title: Request a Digital Shelf Intelligence Report
description: How to retrieve weekly aggregated shelf performance, visibility, and competitive benchmark data for brands and products.
---

This guide covers submitting a Digital Shelf Intelligence report and downloading the results. By the end, you will have a weekly report with sales, visibility, and benchmark metrics at brand or SKU level.

<Note>
  Regional availability: **United States (US)**, **Canada (CA)**, and **United Kingdom (UK)** only.
</Note>

---

## Prerequisites

- **Auth scope**: `retail-media:read` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Account ID**: a numeric `accountId` with access to shelf intelligence data — obtained from [your account list](/retail-media/experimental/reference/gateway/get-me)

---

## Steps

### 1. Submit the report request

[→ `POST /retail-media/insights/digital-shelf-intelligence`](/retail-media/experimental/reference/analytics/create-digital-shelf-intelligence)

Provide `accountId`, `startDate`, `endDate`, `aggregationLevel`, and at least one `metrics` value. All five are required.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/insights/digital-shelf-intelligence" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "attributes": {
        "accountId": "4567891234567891",
        "startDate": "2026-10-06",
        "endDate": "2026-10-12",
        "aggregationLevel": "sku",
        "metrics": ["totalSalesOnline", "totalSoldUnitsOnline", "listingPrice"],
        "filters": {
          "retailerIds": ["1141"],
          "categories": ["Beverages"]
        },
        "format": "json-compact"
      }
    }
  }'
```

Save `data.id` from the response — this is the `insightId` used to poll for status.

<Warning>
  Dates are automatically shifted to week boundaries (Monday–Sunday) if not aligned. The response will include a warning when this happens. Send Monday–Sunday dates to avoid auto-adjustment.
</Warning>

<Note>
  `filters.skuIds` is ignored with a warning when `aggregationLevel` is `brand`.
</Note>

### 2. Poll for status

[→ `GET /retail-media/insights/{insight-id}/status`](/retail-media/experimental/reference/analytics/get-insight-status)

Poll until `data.attributes.status` is `success`. Retry on `pending`. On `failure`, the request was invalid — do not retry without changing the parameters.

### 3. Download the output

[→ `GET /retail-media/insights/{insight-id}/output`](/retail-media/experimental/reference/analytics/get-insight-output)

Returns the report in the format specified at submission. Output columns depend on `aggregationLevel`: brand-level groups across all SKUs; SKU-level reports per individual product.

---

## Verify

A successful submission returns HTTP `200` with `data.attributes.status: pending` and a `data.id`. After polling to `success`, the output returns shelf intelligence data. A `400` with `invalid-date` means dates were auto-shifted — check the `warnings` array in the submission response.

---

## Constraints

| Limit | Value |
|---|---|
| Max date range | 100 days |
| Date alignment | Monday–Sunday weeks — auto-shifted with warning if misaligned |
| `aggregationLevel` | `brand` or `sku` |
| Available metrics | `considerationIndex`, `listingPrice`, `pdpViewRank`, `salesIndex`, `salesRank`, `totalPdpPageViews`, `totalSalesOnline`, `totalSoldUnitsOnline` |
| Regions | US, CA, UK only |
