---
title: Create and Manage Third-Party Accounts
description: How to programmatically create demand brand and seller accounts under a private market supply account as a third-party partner.
---

This guide covers creating demand brand and seller accounts under a parent supply account, and managing their brand and seller mappings. By the end, you will have a working account creation flow for third-party private market integrations.

<Warning>
  Third-party account creation and management access is only available to a selected group of API users. Contact Criteo to enable the correct permissions before using these endpoints.
</Warning>

---

## Prerequisites

- **Auth scope**: `retail-media:manage` — see [Authentication](/retail-media/experimental/docs/authentication)
- **Parent supply account ID**: the `accountId` of the supply account under which child accounts will be created — provided by your Criteo account manager
- **Brand or seller IDs**: brand IDs from the Criteo brand catalog, or seller and retailer IDs from the retailer's catalog

---

## Steps

### 1. Create a seller account

[→ `POST /retail-media/third-party-accounts/{accountId}/create-seller-account`](/retail-media/experimental/reference/thirdpartyaccounts/create-seller-account)

Provide `name`, the `sellers` array (each entry requires `sellerId` and `retailerId`), and optionally `companyName` and `onBehalfCompanyName` for EU DSA compliance.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/third-party-accounts/425730879617900544/create-seller-account" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "RetailMediaSellerAccountCreationV2",
      "attributes": {
        "name": "Town Supplies (seller)",
        "companyName": "Seller Test",
        "onBehalfCompanyName": "Seller Test LLC",
        "sellers": [
          {
            "sellerId": "62a0871ffad67c541xxxxxxxxx",
            "retailerId": "1141"
          }
        ]
      }
    }
  }'
```

Save `data.id` from the response — this is the new demand seller account ID used in subsequent calls.

### 2. Create a brand account

[→ `POST /retail-media/third-party-accounts/{accountId}/create-brand-account`](/retail-media/experimental/reference/thirdpartyaccounts/create-brand-account)

Provide `name` and a `brands` array of brand IDs. Use `companyName` and `onBehalfCompanyName` for EU DSA compliance.

### 3. Manage brand mappings

[→ `POST /retail-media/third-party-accounts/{accountId}/brands/add`](/retail-media/experimental/reference/thirdpartyaccounts/add-brands-to-account) · [→ `POST /retail-media/third-party-accounts/{accountId}/brands/{brandId}/remove`](/retail-media/experimental/reference/thirdpartyaccounts/remove-brand-from-account)

Add or remove brand IDs from an existing demand brand account at any time after creation.

### 4. Manage seller mappings

[→ `PUT /retail-media/third-party-accounts/{accountId}/sellers`](/retail-media/experimental/reference/thirdpartyaccounts/update-sellers-of-account)

<Warning>
  `PUT` replaces the full seller list. Only sellers included in the payload will remain associated with the account — any sellers omitted are removed.
</Warning>

---

## Verify

A successful account creation returns HTTP `201` with the new account's `data.id`. Confirm `data.attributes.type` is `Demand` and `data.attributes.subType` is `Seller` or `Brand`.
