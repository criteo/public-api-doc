---
title: Manage Line Item Products
description: How to add and remove products from a line item's product pool, and fetch the current pool.
---

This guide covers adding products to a line item's promotion pool, removing products, and retrieving the current pool. By the end, products will be available for the line item to promote and ready for creative assignment.

---

## Prerequisites

- **Auth scope**: `retail-media:manage` for add/remove, `retail-media:read` for fetch — see [Authentication](/retail-media/experimental/docs/authentication)
- **Line item ID**: an existing `lineItemId` from [Create and Submit a Line Item](/retail-media/experimental/docs/line-items-core)
- **Product IDs**: product IDs from your account's [catalog](/retail-media/experimental/docs/catalogs) — only products present in the retailer catalog are accepted

<Info>
  Add and remove currently support Onsite Display Auction line items (`productType: DisplayProduct`). Fetch supports both Onsite Display and Sponsored Products line items.
</Info>

---

## Steps

### 1. Add products to the pool

[→ `POST /retail-media/line-items/{line-item-id}/products/add`](/retail-media/experimental/reference/line-item/add-line-item-products)

Provide an array of product resources, each with `id`, `type: LineItemProduct`, `productType: DisplayProduct`, and an empty `displayProductDetails: {}`.

```bash
curl -X POST "https://api.criteo.com/experimental/retail-media/line-items/112233445566778899/products/add" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {
        "id": "sku-12345",
        "type": "LineItemProduct",
        "attributes": {
          "productType": "DisplayProduct",
          "displayProductDetails": {}
        }
      }
    ]
  }'
```

<Warning>
  Add is all-or-nothing — if any product fails validation (e.g., not in the retailer catalog), the entire request fails and the pool is unchanged. Adding a product already in the pool is a no-op.
</Warning>

### 2. Fetch the product pool

[→ `GET /retail-media/line-items/{line-item-id}/products`](/retail-media/experimental/reference/line-item/get-line-item-products)

Returns a paginated list of products currently in the pool. Products are returned in ascending `productId` order. Each product includes its `approvalStatus` for display products or `status` for sponsored products.

### 3. Remove products from the pool

[→ `POST /retail-media/line-items/{line-item-id}/products/delete`](/retail-media/experimental/reference/line-item/delete-line-item-products)

Pass product IDs in the `productIds` array inside a single resource. Removal is idempotent — IDs not in the pool generate a `product-already-deleted` warning but the request still succeeds.

<Warning>
  The `/products/delete` path exists on both experimental and stable but the request body is different. On experimental, send `data.attributes.productIds` (array of ID strings). On stable versions, send an array of product resources. Using the wrong body shape silently does nothing or errors.
</Warning>

---

## Verify

A successful add returns HTTP `200` with `data` listing the added products and their `approvalStatus: Unsubmitted`. After retailer approval, `approvalStatus` becomes `Approved`. A `200` from remove returns empty `warnings` and `errors` arrays — use a fetch to confirm the pool state.

---

## Constraints

| Limit | Value |
|---|---|
| Max products per request / pool | 1,500 |
| Fetch page `limit` | 1–1,000 (default 500) |
| Products added to | Pool only — not automatically assigned to Creative Product Collections |
| Remove behavior | Soft delete — product removed from pool and proposal, stays in catalog |
| Duplicate IDs in request | Deduplicated case-insensitively — added or removed once |
