---
title: Monitor Catalog Ingestion
description: How to check catalog import status, diagnose data quality issues, and retrieve quality scores for a merchant.
---

Use these endpoints to verify that catalog imports are running and to identify what's blocking or failing them. The `quality` report endpoint is new in `2027.01` — it returns per-field quality scores not available in stable.

---

## Prerequisites

- **Auth scope**: `retail-media:read` — see [Authentication](/retail-media/v2027.01-rc/docs/authentication)
- **Merchant ID**: the `merchant-id` whose ingestion history to retrieve

---

## Steps

### 1. List recent ingestions

[→ `GET /retail-media/catalog/merchants/{merchant-id}/ingestion/reports`](/retail-media/v2027.01-rc/reference/catalog/list-ingestion-reports)

Returns recent ingestion runs ordered most-recent-first. Check `ingestionStatus` for each run:

| Status | Meaning |
|---|---|
| `inProgress` | Still running — poll again |
| `finished` | Completed successfully |
| `failed` | System error — fetch the summary report |
| `blocked` | Failed data quality validation — fetch the quality report to identify failing fields |

```bash
curl -X GET "https://api.criteo.com/2027-01/retail-media/catalog/merchants/987654321/ingestion/reports?limit=25&offset=0" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Accept: application/json"
```

Save `data[].id` from any `blocked` or `failed` entry — this is the `ingestionId` for the next steps.

### 2. Fetch the ingestion summary

[→ `GET /retail-media/catalog/ingestion/{ingestion-id}/reports/summary`](/retail-media/v2027.01-rc/reference/catalog/get-ingestion-summary)

Returns trigger, volume counts, delta (added/updated/deleted/unchanged offers), and high-level data quality breakdowns.

### 3. Fetch the quality report _(new in 2027.01)_

[→ `GET /retail-media/catalog/ingestion/{ingestion-id}/reports/quality`](/retail-media/v2027.01-rc/reference/catalog/get-ingestion-quality)

Returns per-field quality scores and rejection counts. Use this when `ingestionStatus` is `blocked` to identify which specific fields are causing the catalog to fail validation.

---

## Verify

A successful list returns HTTP `200` with a `data` array. For a healthy catalog, the most recent entry has `ingestionStatus: finished`. A `blocked` ingestion means the catalog was not published — use the quality report to identify the failing fields before resubmitting.

---

## Constraints

| Limit | Value |
|---|---|
| List page size | 1–100 (default 25) |
| `ingestionType` | `catalogImport` or `productImporter` |
| `blocked` status | Not a system failure — data quality threshold not met; catalog not published |
| Quality report | Available for `blocked` ingestions; new endpoint in `2027.01` |
