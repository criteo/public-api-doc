title: Report Campaign Performance
description: Flexible campaign performance reporting for Retail Media DSP partners.
---

Flexible performance reporting across any level of granularity. Scope the report to an account, campaign, or line item — the output granularity is determined by the dimensions you include. By the end of this guide, you will have a working async report request returning campaign performance data.

Supports the full set of performance metrics and dimensions, including video, new-to-brand, and keyword data.

## Prerequisites

- Authenticated with scope `retail-media:read`
- Account, campaign, or line item ID to scope the report

## Steps

### 1. Submit the report request

[→ `POST /retail-media/reports/performance`](/retail-media/reference/generate-async-performance-report)

This endpoint is asynchronous — see [Async Patterns](/retail-media/docs/async-patterns).

Provide exactly one scope filter (`accountIds`, `campaignIds`, or `lineItemIds`), plus `startDate`, `endDate`, `metrics`, and `dimensions`. All five are required.

```bash
curl -X POST "https://api.criteo.com/2026-07/retail-media/reports/performance" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "attributes": {
        "filters": {
          "accountIds": ["4567891234567891"]
        },
        "startDate": "2026-10-01",
        "endDate": "2026-10-31",
        "metrics": ["impressions", "clicks", "spend"],
        "dimensions": ["date", "campaignId"]
      }
    }
  }'
```

Save `data.id` from the response — this is the `reportId` used in steps 2 and 3.

<Warning>`filters` must contain exactly one scope filter. Passing multiple or none returns `400 Bad Request`.</Warning>

<Note>The `winRate` metric is meaningful only for Sponsored Products campaigns. If your account also runs other campaign types, include `campaignType` in `dimensions` (or filter to Sponsored Products) so `winRate` is attributed to the right campaigns.</Note>

---

### 2. Poll for status

Poll `data.id` using the status endpoint — see [Async Patterns](/retail-media/docs/async-patterns).

Retry on `pending` or `running`. A `failure` status means the request was invalid — do not retry without changing the parameters.

---

### 3. Download the result

Once status is `success`, retrieve the output — see [Async Patterns](/retail-media/docs/async-patterns).

Output defaults to `json-compact` — a `columns`/`data` array shape rather than an array of row objects. Set `format: csv` in the original request if you prefer a flat file.

---

## Verify

A successful response has HTTP `200` with `data.attributes.status: success` and a non-empty `data.attributes.outputUri`. If `outputUri` is null, the report ran but returned no data for the requested date range and filters.

---

## Constraints

| Limit | Value |
|---|---|
| Max date range | 100 days — [Hard Limits](/retail-media/docs/hard-limits) |
| Data retention | 3 years |
