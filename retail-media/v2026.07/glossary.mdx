---
title: Glossary
description: Definitions for the terms used across Commerce Max and the Retail Media API.
---

Several terms in the Retail Media API cluster around the retailer side of the ecosystem and are easy to conflate. This page defines each one.

**Commerce Max (CMax)** — Criteo's retail media platform. Brands and agencies use it to activate Onsite and Offsite campaigns. Most API workflows operate within Commerce Max.

**Demand account** — an account held by a brand, agency, or seller that buys advertising. Two subtypes: Demand-Brand and Demand-Seller.

**Supply account** — an account held by a retailer that manages ad inventory. Has access to both supply-side and demand-side features in Commerce Max.

**Private Market** — a retailer-controlled campaign environment, distinct from Commerce Max. Not an account type — it describes how campaigns are activated. Campaigns appear in reporting with an `Activation platform` dimension of either `Commerce Max` or `Private Market`.

**Retailer** — a Retail Media entity identified by a `retailerId`. Distinct from a Supply account (`accountId`) — related but not the same object or identifier.

**Partner** — a label used only in the context of the Partner Billing Report. It refers to the retailer in a billing relationship where the retailer bills advertisers who contracted directly with them. Not an account type and not interchangeable with `retailerId`.

**Criteo Budget** — the default budget model. Balances under this model are created and managed in the Commerce Max UI, not via the API.

**Retailer Budget** — an alternative budget model where the retailer funds working media directly. Requires retailer authorization. Balances are read-only via the API — amounts and metadata are managed by Criteo on behalf of the retailer.
