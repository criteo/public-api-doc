---
title: Manage Promoted Products
description: How to add, update, and remove promoted products on a Sponsored Products line item.
---

Promoted products are the SKUs your Sponsored Products line item serves ads for. By the end of this guide, you will have products added to a line item with optional per-product bid overrides set.

**Use this guide if you** are building or maintaining a Sponsored Products line item and need to control which SKUs it promotes.

## Prerequisites

- Authenticated with scope `retail-media:read` and `retail-media:write`
- Line item ID (`lineItemId`) — from campaign creation
- SKU IDs to promote — use [Retrieve Catalog Data](/retail-media/docs/catalog-retrieval) to discover available products

## Steps

### 1. List current products

[→ `GET /retail-media/line-items/{lineItemId}/products`](/retail-media/reference/get-line-item-products)

Returns the current product set. Each item has `attributes.id` (the retailer SKU), `attributes.status` (`active`, `paused`, or `unknown`), and `attributes.bidOverride` if one is set.

---

### 2. Append products

[→ `POST /retail-media/line-items/{lineItemId}/products/append`](/retail-media/reference/append-line-item-products)

Pass an array of SKUs to add. Set `bidOverride` per product to override the line item's default bid for that SKU — omit it to use the default.

```bash
curl -X POST "https://api.criteo.com/2026-07/retail-media/line-items/9876543210987654/products/append" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {
        "attributes": {
          "id": "SKU-12345",
          "bidOverride": 2.50
        }
      },
      {
        "attributes": {
          "id": "SKU-67890"
        }
      }
    ]
  }'
```

<Warning>`bidOverride` is only applied during `/append`. It is silently ignored by `/delete`, `/pause`, and `/unpause` — to update a bid override, delete and re-append the product.</Warning>

---

### 3. Pause, unpause, or delete products

**Pause** — stops the product from serving but keeps it on the line item:

[→ `POST /retail-media/line-items/{lineItemId}/products/pause`](/retail-media/reference/pause-line-item-products)

**Unpause:**

[→ `POST /retail-media/line-items/{lineItemId}/products/unpause`](/retail-media/reference/unpause-line-item-products)

**Delete** — permanently removes the product from the line item:

[→ `POST /retail-media/line-items/{lineItemId}/products/delete`](/retail-media/reference/delete-line-item-products)

All three take the same body shape as append — an array of `{"attributes": {"id": "SKU-ID"}}` objects. The `bidOverride` field is accepted but ignored.

---

## Verify

A successful append returns `HTTP 200`. Call `GET /line-items/{lineItemId}/products` to confirm the SKUs appear with `status: active`. A line item with no active products will not serve impressions.
