---
title: Real-Time Performance Report
description: Retrieve near real-time campaign performance data synchronously.
---

Synchronous reporting endpoint for near real-time campaign performance data. Unlike the async reporting endpoints, this returns data immediately with no polling step.

**Designed for:**
- Real-time monitoring during major retail events (Black Friday, Prime Day, etc.)
- Live optimization dashboards for trading teams
- Alerting systems reacting to sudden performance changes

<Info>
  - ~**15 minute latency** from impression/click to availability
  - **7-day lookback** maximum
  - **Onsite campaigns only**
  - Focused metric set: `impressions`, `clicks`, `spend`
</Info>

<Warning>
  **Metric rename from Preview:** `billableImpressions` and `billableClicks` have been renamed to `impressions` and `clicks` in the stable API. These now count total volume (billable + non-billable). Update field mappings before migrating from Preview.
</Warning>

## Prerequisites

- Authenticated with scope `retail-media:read`
- Account, campaign, or line item ID to scope the report (exactly one required, max 50 IDs)

## Steps

### 1. Request

[→ `POST /retail-media/reports/sync/real-time-performance`](/retail-media/reference/generate-sync-real-time-performance-report)

Provide `startDate`, at least one dimension, at least one metric, and exactly one entity filter (`accountIds`, `campaignIds`, or `lineItemIds`).

<Warning>Exactly one entity filter must be provided. Passing multiple or none returns `400 Bad Request`.</Warning>

Returns data immediately — no polling required.

### 2. Read the response

The response includes a `meta.dataCompleteThrough` field indicating the timestamp up to which data is complete in the requested timezone. Use this to understand the freshness boundary of the returned data.

## Constraints

| Limit | Value |
|---|---|
| Lookback window | 7 days from now in the requested timezone |
| Max IDs per filter | 50 |
| Available metrics | `impressions`, `clicks`, `spend` |
