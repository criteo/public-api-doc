---
title: Manage Store Inventory
description: Send real-time store-level price and availability updates using the Store Inventory API.
---

Send batched inventory events (upserts and deletes) to keep store-level product availability and pricing current. This powers accurate PDP and ad experiences at the store level.

<Note>
  Each event in a batch must have a unique `batchId` per request.
</Note>

## Prerequisites

- Authenticated with scope for catalog management (contact Criteo for the required scope)
- Merchant ID (`merchantId`) — your `partnerId` in Criteo systems

## Regional URLs

| Region | Base URL |
|---|---|
| Americas | `api.us.criteo.com` |
| APAC | `api.as.criteo.com` |
| EMEA | `api.eu.criteo.com` |

## Steps

### 1. Upsert inventory

[→ `POST /retail-media/catalog/merchants/{merchantId}/store-inventory/upsert`](/retail-media/reference/catalog/upsert-store-inventory-per-merchant-id)

Send a batch of insert or update events. Each item in `data` requires `batchId`, `productId`, `storeId`, `availability`, and `price`.

```bash
curl -X POST "https://api.us.criteo.com/2026-07/retail-media/catalog/merchants/12345/store-inventory/upsert" \
  -H "Authorization: Bearer <MY_ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {
        "type": "Upsert",
        "attributes": {
          "batchId": "batch1",
          "productId": "product1",
          "storeId": "store1",
          "availability": "in_stock",
          "price": "19.99",
          "salePrice": "10.99"
        }
      }
    ]
  }'
```

<Warning>Each request can contain at most 1000 events. Exceeding this limit returns `400 Request too large`.</Warning>

A successful upsert returns `HTTP 204 No Content` with an empty payload.

---

### 2. Delete inventory

[→ `POST /retail-media/catalog/merchants/{merchantId}/store-inventory/delete`](/retail-media/reference/catalog/delete-store-inventory-per-merchant-id)

Send a batch of delete events. Each item requires `batchId`, `productId`, and `storeId`. The `availability` and `price` fields are not needed for deletes.

A successful delete returns `HTTP 204 No Content` with an empty payload.

---

## Verify

A successful operation returns `HTTP 204 No Content` with an empty payload. Any error returns a non-2xx status with an error body.

---

## Field reference

| Field | Required | Type | Constraints |
|---|---|---|---|
| `batchId` | Yes | string | Must be unique per request |
| `productId` | Yes | string | Up to 50 characters |
| `storeId` | Yes | string | Up to 64 characters |
| `availability` | Yes (upsert) | enum | `in_stock`, `out_of_stock`, `preorder`, `backorder` |
| `price` | Yes (upsert) | string | Up to 14 characters |
| `salePrice` | No | string | Up to 14 characters |

## Common errors

| Code | Error | Cause |
|---|---|---|
| `400` | Bad request | Missing required fields; non-unique `batchId`/`productId`/`storeId` combination |
| `400` | Request too large | Payload exceeds 1000 events |
| `401` | Unauthorized | Authentication required |
| `403` | Forbidden | Not authorized for this merchant ID |
| `429` | Too Many Requests | Rate limit exceeded |
