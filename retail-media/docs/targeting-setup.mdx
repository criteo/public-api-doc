title: Set Up Targeting
description: How to configure audience, store, and add-to-basket targeting on line items.

Targeting determines which shoppers and placements your line item reaches. Three targeting sub-resources can be configured on a line item: **audience segments**, **stores**, and **add-to-basket**. By the end of this guide, you will have one or more targeting types configured on a line item.

<Warning>
  **Request/response schemas not yet published in the API Reference.** The targeting endpoints below exist and are operational, but their schemas are absent from the current OAS. Curl examples and field details will be added when the schemas are published. Contact your Criteo account team for current field details.
</Warning>

## Prerequisites

- Authenticated with scope `retail-media:read` and `retail-media:write`
- Line item ID (`lineItemId`)
- For audience targeting: audience segment IDs — see [Discover audience segments](#discover-audience-segments) below

## The initialize-before-append pattern

All three targeting sub-resources require initialization before append or delete operations will work:

1. **Initialize** with `PUT` to set the scope and initial state
2. **Append** additional items with `POST`
3. **Remove** items with `DELETE`

Sending `POST` or `DELETE` without a prior `PUT` returns a `4xx` error. See [Initialize Before Append](/retail-media/docs/initialize-before-append) for the full list of affected resources.

## Audience targeting

### Discover audience segments

[→ `POST /retail-media/accounts/{accountId}/audience-segments/search`](/retail-media/reference/search-audience-segments)

Search for audience segments available to the account. Use the returned segment IDs in the steps below.

### Configure

**Initialize:**
```
PUT /retail-media/line-items/{lineItemId}/targeting/audiences
```

**Append segments:**
```
POST /retail-media/line-items/{lineItemId}/targeting/audiences
```

**Remove segments:**
```
DELETE /retail-media/line-items/{lineItemId}/targeting/audiences
```

## Store targeting

Restrict the line item to serve only in specific stores.

**Initialize:**
```
PUT /retail-media/line-items/{lineItemId}/targeting/stores
```

**Append stores:**
```
POST /retail-media/line-items/{lineItemId}/targeting/stores
```

**Remove stores:**
```
DELETE /retail-media/line-items/{lineItemId}/targeting/stores
```

---

## Add-to-basket targeting

Target shoppers based on products or categories currently in their basket.

**Initialize:**
```
PUT /retail-media/line-items/{lineItemId}/targeting/add-to-basket
```

**Append:**
```
POST /retail-media/line-items/{lineItemId}/targeting/add-to-basket
```

**Remove:**
```
DELETE /retail-media/line-items/{lineItemId}/targeting/add-to-basket
```

<Warning>`productIds` and `categoryIds` are mutually exclusive within a single add-to-basket scope — a scope can target one or the other, not both.</Warning>

---

## Verify

If a `POST` or `DELETE` returns `4xx`, check that the scope was initialized with `PUT` first — this is the most common cause. See [Initialize Before Append](/retail-media/docs/initialize-before-append).
