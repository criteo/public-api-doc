Criteo's **Campaign API** allows you to retrieve information about the current configuration of your advertising Ad Sets.

This API allows you to **create** adSets, **search** for Ad Sets based on filters, **start and stop** Ad Sets, and **update** your Ad Sets' names, start and end dates, bid amounts, frequency capping, and other targeting controls.

## **Ad Set Attributes**

**`name`**  
The Ad Set name, set by the advertiser.

**`destinationEnvironment`**  
Read-only. The environment that an ad click will lead a user to.

**`objective`**  
The outcome the Ad Set is intended to optimize.

Supported values are `customAction`, `clicks`, `conversions`, `displays`, `appPromotion`, `revenue`, `storeConversions`, `reach`, `visits`, and `videoViews`.

An objective is not necessarily supported for every media type and cost controller. The API validates `objective`, `mediaType`, and `bidding.costController` together. See [Cost-controller compatibility](#cost-controller-compatibility) before creating an Ad Set.

`videoViews` is supported only when `mediaType` is `video`. `revenue` is not supported when `mediaType` is `video` and `bidding.costController` is `dailyBudget`.

**`mediaType`**  
The type of media the ad set will deliver on. Can be `display` or `video`

**`datasetId`**  
Data Set Id associated with the specified advertiser ID. See [Datasets](/marketing-solutions/v2026-preview/docs/datasets)  for how to find datasets associated to advertisers.

**`campaignId`**  
Id of the marketing campaign associated to the ad set. See [Search for Campaigns](/marketing-solutions/docs/campaign#searching-campaigns) for how to search for campaigns.

**`adSetType`**  
The type of the Ad Set. Can be:
- `standard`: a regular Ad Set. This is the default when `adSetType` is omitted on creation.
- `appRetargeting`: an App Retargeting Ad Set, which retargets users of an Android or iOS app. See [Create an App Retargeting Ad Set](#create-an-app-retargeting-ad-set).
- `unknown`: read-only value, only returned when retrieving Ad Sets, for any other type of Ad Set. It is rejected on creation.

The type is set at creation and cannot be changed via the `PATCH` endpoint.

**`serverToServerTrackings`**  
Optional and only supported on `appRetargeting` Ad Sets. List of server-to-server (MMP) tracking URLs of the Ad Set. Each entry contains a `url` of at most 1024 characters. The number of trackings per Ad Set is limited, currently to 5. If the limit is exceeded, the error returned gives the current limit.  
The app environment of the tracking (Android or iOS app) is derived from the operating system targeted by the Ad Set.  
Returned only when retrieving a single Ad Set by ID, where it is `null` if the Ad Set has no tracking, is not an App Retargeting Ad Set, or if its trackings cannot be retrieved. It is never returned by the search endpoint.

### Ad Set Schedule

**`schedule.startDate`**  
ISO 8601 format. It must always be earlier than the `schedule.endDate`. It's a mandatory parameter of the Schedule object. This condition applies only if an `endDate` is defined.

**`schedule.endDate`**  
ISO 8601 format. `null` by default. (`null` is a valid value.)

**`schedule.activationStatus`**  
Can be `on` or `off`. `off` by default. Set by the advertiser, this represents the intent to deliver ads. See [Start and Stop Ad Sets](/marketing-solutions/docs/ad-set#start-an-ad-set) for how to change this value.

**`schedule.deliveryStatus`**  
Can be `draft`, `inactive`, `live`, `notLive`, `pausing`, `paused`, `scheduled`, `ended`, `notDelivering`, or `archived`.  The initial value for a newly created Ad Set is `draft`. This is a **computed value** and is read-only.

<Warning>
  **`activationStatus` vs `deliveryStatus`**

  `deliveryStatus` is a computed value. It is affected by factors other than the value of `activationStatus`, such as budget consumption, start date, and end date.
</Warning>

### Ad Set Bidding

**`bidding.bidAmount`**  
Decimal value target relating to the `objective` specified. May be `null` for strategies that do not require a target value.

**`bidding.costController`**  
How spend is controlled and optimized. Can be `COS` (Cost of Sale), `MaxCPC` (Cost per Click), `CPI` (Cost per Install), `CPM` (Cost per Mille), `CPO` (Cost per Order), `CPSV` (Cost per Site Visit), `CPV` (Cost per View), `targetCPM` or `dailyBudget`.

### Cost-controller compatibility

A cost-controller value is not valid with every combination of `mediaType` and `objective`. The API uses these three fields together to select the Ad Set's optimization model.

For budget-controlled performance Ad Sets, the following combinations are supported:

| `mediaType` | `objective` | `bidding.costController` | Optimization behavior |
|---|---|---|---|
| `display` | `visits` | `dailyBudget` | Maximize qualified visits while delivering toward the budget. |
| `display` | `conversions` | `dailyBudget` | Maximize attributed conversions while delivering toward the budget. |
| `display` | `revenue` | `dailyBudget` | Maximize attributed revenue or order value while delivering toward the budget. |
| `video` | `visits` | `dailyBudget` | Maximize attributed post-view visits while delivering toward the budget. |
| `video` | `conversions` | `dailyBudget` | Maximize attributed post-view conversions while delivering toward the budget. |

<Warning>
  **Video revenue optimization is not supported**

  Do not combine `mediaType: video`, `objective: revenue`, and `bidding.costController: dailyBudget`. Criteo does not currently provide a budget based video optimization model for attributed revenue or order value. Use `objective: conversions` to optimize a video Ad Set for post-view conversions.
</Warning>

Unsupported combinations are rejected during Ad Set creation with the `campaign--ad-set-creation-check--invalid-bidding-configuration` validation error.

### Ad Set Targeting

**`targeting.frequencyCapping.maximumImpressions`**  
Integer value. The maximum impressions allowed for the specified `frequencyCapping.frequency`.

**`targeting.frequencyCapping.frequency`**  
The period by which the maximum impression limit is calculated. Can be `hourly`, `daily`, or `lifetime`.  `advanced` is available for special Criteo-configured setups, but cannot be selected or set manually.

**`targeting.geoLocation.countries`**  
Contains an array of `values`, two letter country codes, [ISO-3166 format](https://www.iso.org/iso-3166-country-codes.html). Also specifies an `operand` which can be `in` or `notIn` depending on the desired behavior for the `values`.

**`targeting.geoLocation.subdivisions`**  
Contains an array of `values`, geographical subdivisions following [ISO-3166 format](https://www.iso.org/iso-3166-country-codes.html). Also specifies an `operand` which can be `in` or `notIn` depending on the desired behavior for the `values`.

**`targeting.geoLocation.zipCodes`**  
Contains an array of `values`, zip codes. Also specifies an `operand` which can be `in` or `notIn` depending on the desired behavior for the `values`.

<Warning>
  **Geolocation Targeting**

  Geolocation settings do not support an empty array for their `values`. If a geolocation setting like `geoLocation.countries` is `null`, then the filter is inactive. Otherwise, the filter is active and must have a non-empty list for `values`.
</Warning>

**`targeting.deliveryLimitations.devices`**  
List of device types that the Ad Set should target. Can contain `desktop`, `tablet`, `mobile` and `other`.

**`targeting.deliveryLimitations.operatingSystems`**  
List of operating systems that the Ad Set should target. Can contain `android`, `ios`, and `other`.

**`targeting.deliveryLimitations.environments`**  
List of display environments that the Ad Set should target. Can contain `inApp` and `web`.

### Ad Set Budget

**`budget.budgetStrategy`**  
Whether the Ad Set budget is capped or not. Can be `capped` or `uncapped`. This field can be updated via the `PATCH` endpoint.

**`budget.budgetRenewal`**  
The cadence of budget renewal. Can be `daily`, `weekly`, `monthly`, `lifetime`, or `undefined`. The value `undefined` is only allowed when `budgetStrategy` is `uncapped`. Capped budgets must use `daily`, `weekly`, `monthly`, or `lifetime`. This field can be updated via the `PATCH` endpoint.

**`budget.budgetDeliverySmoothing`**  
Pacing strategy for spending the budget within a renewal period. Only applicable when `budgetStrategy` is `capped`.
`accelerated`: spend pacing is based on delivery efficiency rather than the full budget period.
`standard`: spread spending evenly over the renewal period.
When `budgetStrategy` is `uncapped`, this field is not set (`null` in read responses, omitted in create/patch requests). This field can be updated via the `PATCH` endpoint.

**`budget.budgetDeliveryWeek`**  
The seven day period used for weekly budget delivery. Can be `mondayToSunday`, `tuesdayToMonday`, `wednesdayToTuesday`, `thursdayToWednesday`, `fridayToThursday`, `saturdayToFriday`, or `sundayToSaturday`.
This field is only applicable when `budgetStrategy` is `capped`, `budgetRenewal` is `weekly`, and `budgetDeliverySmoothing` is `standard`.
For non-weekly budgets, this value should be `undefined`. This field can be updated via the `PATCH` endpoint.

**`budget.budgetAmount`**  
A decimal value showing the remaining budget value for Ad Sets with `Capped` budget strategies. For uncapped budgets, the value will be `null`.

**`budget.pacingBehavior`**  
Controls how a standard capped budget is paced. Nullable. Possible values:
- `targetFullBudget`: spend toward the full budget amount within the renewal period.
- `targetAverageDailyBudget`: spend toward an average daily amount. Only supported for capped, standard, monthly budgets.
- `undefined`: no explicit pacing behavior. Required for uncapped budgets and accelerated budgets.

### Ad Set Attribution Configuration

**`attributionConfiguration.attributionMethod`**

The attribution method that defines how sales will be attributed to the marketing campaign. Can be `criteoAttribution` (default), `lastClick`, `postClick`, `sftp`, or `googleAnalytics`.

**`attributionConfiguration.lookbackWindow`**

The lookback window specifies the time frame during which purchases are attributed to an ad interaction. Can be `30M (Same Session)`, `24H`, `7D`, `30D`. It is filled when the `postClick` or `lastClick` attribution method is selected, or else it should not be filled, and would return an error.

## **Searching Ad Sets**

### Retrieving Ad Sets by Filtering

Ad Sets can be retrieved by specifying filters to apply to the set of all Ad Sets in your portfolio.

Current available filters are `adSetIds` (which allows you to specify a list of Ad Set IDs to retrieve), `campaignIds` (which allows you retrieve Ad Sets belonging to a list of Campaigns)  and `advertiserIds` (which allows you retrieve Ad Sets belonging to a list of Advertisers).

For example, to retrieve two existing Ad Sets in your portfolio, filter by `adSetIds`:

<EndpointBadge method="post">
```http
/marketing-solutions/ad-sets/search
```
</EndpointBadge>

<CodeGroup>

```json JSON Payload
{
    "filters": {
        "adSetIds": ["12345", "67890"] 
    }
}
```
</CodeGroup>

The API will return an array of Ad Sets that match the provided filters:

```json Sample Response
{
    "data": [
        {
            "type": "ReadAdSetV26Q1",
            "id": "12345",
            "attributes": { ... }
        },
            "type": "ReadAdSetV26Q1",
            "id": "67890",
            "attributes": { ... }
        }
    ],
    "warnings": [],
    "errors": []
}
```

The response above is truncated for clarity.

Note: the _type_ field is the type name of the entity, which can change between API versions (for example `ReadAdSetV26Q1` in version 2026.07), and the _id_ field is the unique id of the Ad Set.

<Info>
  **`adSetType` and `serverToServerTrackings` in search results**

  `adSetType` is returned in search results, except when the request uses field projection (`meta.fields`).
  `serverToServerTrackings` is never returned by the search endpoint. To retrieve it, [retrieve the Ad Set by its ID](#retrieving-one-specific-ad-set).
</Info>
### Retrieving All Ad Sets

When no filters are specified in the JSON payload, all Ad Sets in your portfolio will be returned, as in the example below:

<EndpointBadge method="post">
```http
/marketing-solutions/ad-sets/search
```
</EndpointBadge>

<CodeGroup>

```json JSON Payload
{
    "filters": {}
}
```
</CodeGroup>

### Create an App Retargeting Ad Set

App Retargeting Ad Sets retarget users of your Android or iOS app. They are created with the same endpoint as other Ad Sets. To create one:

* Set `adSetType` to `appRetargeting`.
* Target exactly one operating system in `targeting.deliveryLimitations.operatingSystems`: `android` or `ios`.
* Target `mobile`, `tablet`, or both in `targeting.deliveryLimitations.devices`. No other device type is allowed.

The recommended value for `targeting.deliveryLimitations.environments` is `inApp` and `web`.

App Retargeting Ad Sets also have the following constraints:

* An app homepage deeplink must be configured for the targeted operating system.
* `attributionConfiguration.attributionMethod` can only be `criteoAttribution`, `sftp`, or `googleAnalytics`. `sftp` is only available if SFTP attribution is enabled and set up for the advertiser. `googleAnalytics` is only available if Google Analytics attribution is enabled for App Retargeting for the advertiser.

Optionally, you can attach one or several server-to-server (MMP) trackings to the Ad Set by setting `serverToServerTrackings` in the request `attributes`.

<EndpointBadge method="post">
```http
/marketing-solutions/ad-sets
```
</EndpointBadge>

<CodeGroup>

```json Sample Request Body expandable
{
  "data": {
    "type": "AdSet",
    "attributes": {
      "name": "API created App Retargeting Ad Set",
      "datasetId": "56789",
      "objective": "conversions",
      "campaignId": "12789",
      "mediaType": "display",
      "adSetType": "appRetargeting",
      "schedule": {
        "startDate": "2026-11-16T00:00:00Z"
      },
      "bidding": {
        "costController": "dailyBudget"
      },
      "targeting": {
        "geoLocation": {
          "countries": {
            "values": ["FR", "IT"],
            "operand": "in"
          }
        },
        "deliveryLimitations": {
          "devices": ["mobile", "tablet"],
          "operatingSystems": ["android"],
          "environments": ["inApp", "web"]
        }
      },
      "budget": {
        "budgetStrategy": "capped",
        "budgetRenewal": "weekly",
        "budgetDeliverySmoothing": "standard",
        "budgetDeliveryWeek": "mondayToSunday",
        "budgetAmount": 100,
        "pacingBehavior": "targetFullBudget"
      },
      "attributionConfiguration": {

        {
          "url": "https://app.appsflyer.com/v2.0/s2s/com.example.app?pid=criteonew_int&advertising_id={device_id}&af_c_id={campaignid}&redirect=false&af_ip={user_ip}&af_ua={user_agent_enc}&af_os_version={os_version}&c={adset_name_enc}&af_lang=(|default(language,\"en\")|)&af_siteid={bundle_id}{domain_enc}&is_retargeting=true&af_reengagement_window=30d"

```

<Warning>
  **Server-to-server trackings never block the Ad Set creation**

  The Ad Set is always created and returned with its ID, even if its trackings have issues. Any issue is reported in the `warnings` array of the response:

  * If the trackings fail validation, or if the validation cannot be performed, the trackings are still saved. Trackings that fail validation may not work as expected.
  * The trackings are not saved only if the `campaign--ad-set-creation-check--server-to-server-tracking-save-failed` warning is returned.

  Do not retry the creation, as it would create a duplicate Ad Set: [update the trackings](#update-server-to-server-trackings) of the created Ad Set instead.
</Warning>

## **Update Ad Sets**

The fields of one or more Ad Sets can be updated by making a `PATCH` call to the Ad Sets endpoint. The payload should be an array of partial or whole Ad Sets, each specifying the fields to be modified.

For example, the following call would update the `name`, `startDate`, `endDate`, `bidAmount` and frequency capping settings of an existing Ad Set:

The bid amount value supports a maximum of 4 decimal digits. If more digits are provided, the amount will be rounded.

<EndpointBadge method="patch">
```http
/marketing-solutions/ad-sets
```
</EndpointBadge>

<CodeGroup>

```json Sample Request Body
{
    "data": [
        {
            "type": "PatchAdSetV26Q1",
            "id": "12345",
            "attributes": {
              	"name": "Updated Ad Set Name",
                "scheduling": {
                    "startDate": { "value": "2021-01-19T10:18:28.632Z" },
                    "endDate": { "value": "2021-01-20T10:18:28.632Z" }
                },
                "bidding": {
                    "bidAmount": { "value": 0.9 }
                },
                "targeting": {
                    "frequencyCapping": {
                        "value": {
                            "frequency": "hourly",
                            "maximumImpressions": 12
                        }
                    }
                },
                "budget": {
                    "pacingBehavior": "targetFullBudget"
                },
                "attributionConfiguration": { 
                    "attributionMethod": "lastClick", 
                    "lookbackWindow":  "30D" 
                } 
            }
        }
    ]
}
```
</CodeGroup>

The API will return an array of Ad Sets that have been updated successfully in the response `data`. These will contain only two parameters, `type` and `id`.

```json Sample Response
{
    "data": [
        {
            "type": "AdSetIdV26Q1",
            "id": "12345"
        }
    ],
    "errors": [],
    "warnings": []
}
```

<Warning>
  **Ad Set Patch Limit**

  Note that there is a limit of 50 ad sets per single request. If you are updating more than 50 ad sets, please split them into chunks of 50 and make multiple requests.
</Warning>

### Update an App Retargeting Ad Set

App Retargeting Ad Sets are updated with the same endpoint as other Ad Sets, and the same constraints as on creation apply. In addition:

* `adSetType` cannot be changed.
* `targeting.deliveryLimitations.operatingSystems` cannot be changed.
* `targeting.deliveryLimitations.devices` can be changed, but must still contain `mobile`, `tablet`, or both. It cannot be cleared.

#### Update Server-to-Server Trackings

The `serverToServerTrackings` attribute of an App Retargeting Ad Set can be updated via the `PATCH` endpoint:

* **Omitted or set to `null`**: the trackings are left unchanged.
* **Set to a list**: the trackings are fully replaced by the provided list. This is not a partial update: to change one tracking out of several, provide all of them again, or the ones not provided will be removed.
* **Set to an empty list** (`[]`): all trackings are removed.

<EndpointBadge method="patch">
```http
/marketing-solutions/ad-sets
```
</EndpointBadge>

<CodeGroup>

```json Replace trackings
{
    "data": [
        {
            "type": "PatchAdSetV26Q1",
            "id": "12345",
            "attributes": {
                "serverToServerTrackings": [
```

## **Partial Success / Partial Failure**

Each Ad Set update is processed individually and can succeed or fail without impacting other updates in the same payload.

As a result, those Ad Set updates processed successfully will be returned in the `data` array of the response, while Ad Sets updates that have failed will return as an entry in the `errors` array of the response.

<Warning>
  **HTTP Response Codes**

  As a result of this individual processing, the API may respond with a `200` HTTP response code, but the result of its processing may have one or more failures.
</Warning>

For instance, for this payload which intends to update two Ad Sets:

<EndpointBadge method="patch">
```http
/marketing-solutions/ad-sets
```
</EndpointBadge>

<CodeGroup>

```json Sample Request Body
{
    "data": [
        {
            "type": "PatchAdSetV26Q1",
            "id": "12345",
            "attributes": {
                "bidding": {
                    "bidAmount": { "value": 0.9 }
                }
            }
        },
        {
            "type": "PatchAdSetV26Q1",
            "id": "67890",
            "attributes": {
                "bidding": {
                    "bidAmount": { "value": -2 }
                }
            }
        }
    ]
}
```
</CodeGroup>

The response might look like:

```json Sample Response
{
    "data": [
        {
            "type": "AdSetIdV26Q1",
            "id": "12345"
        }
    ],
    "errors": [
        {
            "traceIdentifier": "56ed4096-f96a-4944-8881-05468efe0ec9",
            "type": "validation",
            "code": "campaign--ad-set-update-check--invalid-bid-amount",
            "instance": "@data/1",
            "title": "Invalid bid amount",
            "detail": "The bid amount value is invalid: either it's an adaptative cost controller and it must be null, or it's not the valid interval of values."
        }
    ],
    "warnings": []
}
```

<Info>
  **Error `instance`**

  The `instance` field for validation errors will specify the index of the related update, beginning with index 0. For the example above, `@data/1` refers to the second requested update in the request's `data` array.
</Info>
